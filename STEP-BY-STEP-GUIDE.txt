**Why audit runs before pre-screen, not after:** audit is cheap (static checks plus one
quick timing pass) and catches things like lookahead bias — which can *inflate* a
pre-screen z-score if left unchecked (a signal peeking at future bars will look like it
has edge when it doesn't). Running audit first means every z-score this pipeline ever
computes was generated by code that already passed structural correctness checks, not the
reverse.

**Why brief and file creation run before pre-screen, not after:** pre-screen calls the
real `signal_fn` — there is nothing to test until Step 1a has written it. Pre-screen is a
filter on a concept that already exists in code; it is not a filter on whether to write
code in the first place.
